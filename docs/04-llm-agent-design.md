# 04. LLM 에이전트 설계

## 1. 에이전트의 역할

자연어 질문을 받아 **온톨로지(그래프) + 시세 + 의미검색**을 도구로 활용해 **근거 기반 답변/종목 신호**를 생성한다.

예시 질의:
- "최근 1주일 호재 뉴스가 집중된 코인은?"
- "삼성전자 주가에 영향 줄만한 최근 이벤트는?"
- "반도체 섹터에서 모멘텀 좋은 종목 알려줘"

## 2. 아키텍처: Tool-calling ReAct 루프

```
사용자 질문
   │
   ▼
[Planner/LLM] ──(어떤 도구가 필요한가?)──► tool_call(name, args)
   ▲                                            │
   │                                            ▼
   └──────── tool_result ◄──────────────  [Tool 실행]
        (관측 → 다음 행동 결정, 반복)
                  │ (충분한 근거 확보)
                  ▼
        [Composer/LLM] → 근거 인용 + 면책 포함 최종 답변
```

- **ReAct**(Reason+Act): LLM이 "생각 → 도구 호출 → 관측 → 재생각"을 반복.
- 도구 호출은 **function calling**으로 구조화(환각 방지).
- 그래프가 **사실의 단일 출처(SSOT)** → 답변 근거를 노드/엣지로 추적 가능.

## 3. 도구(Tools) 카탈로그

| 도구 | 입력 | 출력 | 구현 |
|------|------|------|------|
| `graph_query` | Cypher(또는 자연어→Cypher) | 그래프 결과 | Neo4j 실행, 화이트리스트 검증 |
| `vector_search` | 질의문 | 유사 뉴스 top-k | 임베딩 + Neo4j 벡터 인덱스 |
| `get_price` | symbol, market, interval | 최근 시세/변화율 | Postgres price_bars 조회 |
| `compute_signal` | symbol | 신호 점수(감성·모멘텀·뉴스량) | 그래프+시세 집계 |
| `list_assets` | 필터(섹터/타입) | 자산 목록 | 그래프 조회 |

오LLM이 임의 Cypher를 만들면 위험(삭제/과부하). 방어:
1. **읽기 전용 강제**: `CREATE/DELETE/MERGE/SET/DROP` 포함 시 거부.
2. **LIMIT 강제**: 최종 쿼리에 `LIMIT` 없으면 자동 부착.
3. **타임아웃**: 트랜잭션 타임아웃 설정.
4. **스키마 주입**: 프롬프트에 실제 라벨/관계/속성 제공(존재하지 않는 속성 참조 방지).
5. **파라미터화**: 사용자 값은 파라미터로(인젝션 방지).

## 4. 종목 "추천" 신호 로직 (compute_signal)

추천은 단일 점수가 아니라 **여러 신호의 투명한 합성**으로 만든다(설명가능성).

```
signal(asset) =
    w1 * sentiment_score_7d      # 최근 7일 뉴스 감성 가중합
  + w2 * news_volume_zscore      # 뉴스 언급량의 평소 대비 급증도
  + w3 * price_momentum_7d       # 7일 가격 모멘텀
  + w4 * event_impact            # AFFECTS 엣지 direction*magnitude 합
```

- 각 항을 **개별로 노출**해 "왜 이 신호가 나왔는지" 설명.
- 가중치 `w`는 설정값(`agent/config`)로 외부화 → 정책 변경 용이.
- **절대 "매수하세요"라고 하지 않음** → "관측된 신호" 형태로 제시.

## 5. 그래프 RAG vs 일반 RAG

| | 일반 RAG | 그래프 RAG(본 설계) |
|---|---------|---------------------|
| 검색 단위 | 텍스트 청크 | 노드 + 관계 서브그래프 |
| 답변 근거 | 문서 조각 | "종목-뉴스-이벤트" 연결 경로 |
| 추론 | 약함 | 관계 순회로 다단계 추론 |

본 설계는 **벡터검색(의미 매칭) + 그래프순회(관계 추론)**를 **하이브리드**로 사용한다.
예: "비트코인 관련 호재" → 벡터로 유사 뉴스 찾고 → 그래프로 해당 뉴스의 감성/이벤트/영향 자산 확장.

## 6. 안전장치 (금융 도메인 필수)

| 위험 | 대응 |
|------|------|
| 투자자문 규제 | 출력에 **면책 고지 자동 삽입**, 단정적 표현 금지 |
| 환각 | 그래프에 근거 없는 주장 금지, 모든 수치는 도구 출력 인용 |
| 오래된 정보 | 답변에 데이터 **기준 시각(as-of)** 명시 |
| 데이터 부족 | "근거 부족" 솔직히 답하도록 프롬프트 강제 |
| 프롬프트 인젝션(뉴스 본문 경유) | 뉴스 텍스트는 **데이터로만** 취급, 지시로 해석 금지 |

면책 문구 예:
> ⚠️ 본 정보는 데이터 기반 참고용이며 투자 권유가 아닙니다. 투자 판단과 책임은 본인에게 있습니다. (데이터 기준: {as_of})

## 7. 에이전트 흐름 예시

질문: *"최근 호재가 많은 코인 알려줘"*

```
1. graph_query: asset_type=CRYPTO 자산 목록
2. 각 코인에 대해 compute_signal 호출
   - sentiment_7d, news_volume, momentum, event_impact 수집
3. 점수 정렬 → 상위 N
4. 각 코인의 근거 뉴스(MENTIONS) top-2 인용
5. Composer: 표 + 근거 + 면책으로 자연어화
```

## 파일
- `agent/main.py` — 엔트리포인트(CLI)
- `agent/core/agent.py` — ReAct 루프
- `agent/core/llm.py` — LLM 추상화(function calling) + stub
- `agent/tools/*` — graph_query / vector_search / get_price / compute_signal
- `agent/prompts/system.md` — 시스템 프롬프트(역할·안전·스키마 주입)
